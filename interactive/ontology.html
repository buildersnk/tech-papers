A small interactive lesson for understanding an ontology as a shared model of things, relationships, and the context that makes statements unambiguous.

Core ideaAn ontology is not a list of labels. It is an agreement about what kinds of things exist in a domain and how they may relate.Words become useful when their boundaries and relationships are explicit.

5 · An illustrative ontology

Relationships carry meaning

The same entities support different questions because the predicates are explicit.

{
  "classes": ["Position", "Instrument", "TradingAccount", "LedgerAccount"],
  "relations": {
    "Position —held_in→ TradingAccount": "portfolio ownership",
    "Position —references→ Instrument": "what is traded",
    "Posting —booked_to→ LedgerAccount": "accounting record"
  },
  "constraint": "held_in requires a TradingAccount, not a LedgerAccount"
}
6 · The sequence

How a shared model becomes useful

1. Scope the worldChoose the domain and the questions the model must answer.
2. Name conceptsDefine entities with stable boundaries and identifiers.
3. Add relationsDescribe which connections are allowed and what they mean.
4. Test statementsUse examples and constraints to expose ambiguity.
